## Task 4 — App Privacy (the long one)

Left nav → **App Privacy**. This section may require an Account Holder or Admin role; if
the UI is read-only for the signed-in user, stop and tell the user.

First, the URL at the top of this section:

**Privacy Policy URL:**
```

```

Before entering it, **open that URL in a new tab and confirm it loads and shows actual
policy text.** It is a dynamic route backed by a database table, so it can return a page
that renders but is empty. If it 404s or is blank, **stop and tell the user** — Apple
fetches this URL during review and a dead one is a rejection.

Then the data questionnaire. Start with **"Do you or your third-party partners collect
data from this app?"** → **Yes**.

### The single most important answer

**Tracking is NO for every data type, without exception.** GoHustlr shows no ads, has no
advertising SDK, has no IDFA access and presents no App Tracking Transparency prompt. If
any question asks whether data is used to track users across apps or websites owned by
other companies, the answer is always **No**.

### Data types to select

Select exactly these. For every one, the purpose is **App Functionality** and tracking is
**No**. The "Linked to the user" column is Yes for all of them **except Precise Location**.

| Category | Data type | Linked to user |
|---|---|---|
| Contact Info | Name | Yes |
| Contact Info | Email Address | Yes |
| Financial Info | Payment Info | Yes |
| Financial Info | Other Financial Info | Yes |
| Location | Coarse Location | Yes |
| Location | **Precise Location** | **No** |
| User Content | Photos or Videos | Yes |
| User Content | Customer Support | Yes |
| User Content | Other User Content | Yes |
| Identifiers | User ID | Yes |
| Identifiers | Device ID | Yes |
| Purchases | Purchase History | Yes |
| Other Data | Other Data Types | Yes |

### Data types to leave UNSELECTED

Do not select these, and if any is already selected, deselect it:

- **Phone Number** — never collected
- **Physical Address** — the gig address belongs to the gig, not to a user profile
- **Contacts**, **Browsing History**, **Search History** — not collected
- **Health & Fitness**, **Sensitive Info** — see the note below
- **Usage Data** (Product Interaction, Advertising Data, Other) — see the note below
- **Diagnostics** (Crash Data, Performance Data, Other) — see the note below
- **Emails or Text Messages**, **Audio Data**, **Gameplay Content** — not collected

### Four deliberate calls — do not "fix" these

These look wrong at a glance and are not. Do not change them; if the form seems to
disagree, stop and ask rather than adjusting.

1. **Precise Location is collected but NOT linked to the user.** GPS is read on-device for
   distance sorting and mileage logging and is never persisted against the account. It is
   declared at all only because the published privacy policy says GPS is used, and the
   label must never contradict the policy.
2. **Sensitive Info is NOT collected.** Government ID and selfie go through Stripe
   Identity's hosted flow; the app never receives the document or the image.
3. **Usage Data and Diagnostics are NOT collected.** The analytics and crash-reporting
   keys are unset in this build, so nothing is sent. This is true *today* and will stop
   being true the moment those keys are configured.
4. **In-app messages are declared as "Other User Content", not "Emails or Text
   Messages".** That Apple category is about the user's own email and SMS. This is a
   deliberate choice.

### If asked about "Other Data Types"

It covers **date of birth**, collected once at sign-up to enforce the 18+ requirement.
Purpose App Functionality, linked Yes, tracking No.

Save and publish the privacy section if App Store Connect offers a separate publish step.

## What you CANNOT do — report these, do not attempt them

**"You must choose a build"** cannot be resolved in the browser. It needs a binary
uploaded from a terminal, and there is a blocking mismatch first: the App Store version
string is **1.0** while the project's `app.json` declares **1.4.2**. A build only attaches
to the App Store version matching its `CFBundleShortVersionString`, so a 1.4.2 build will
never appear in the Build picker on a 1.0 page.

Report to the user that they must either set `app.json` → `"version": "1.0.0"` and rebuild,
or rename the App Store version to 1.4.2 — then run `eas build --platform ios --profile
production` followed by `eas submit`. Do not change the version string in App Store Connect
yourself; that decision is the user's.

**iPad screenshots.** If App Store Connect shows an iPad tab requiring screenshots, that is
because the project declares iPad support. Report it and ask the user — the recommendation
on file is to drop the declaration (`app.json` → `ios.supportsTablet: false`) and rebuild
rather than ship an untested iPad layout. Do not upload iPhone screenshots into iPad slots.
